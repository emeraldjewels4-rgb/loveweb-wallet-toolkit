# Exact resolved versions for this project's dependency closure.
#
# ONE pin set governs every interpreter in the CI matrix (3.11, 3.12, 3.13).
# That is what makes the matrix reproducible: all three legs install the same
# versions, so a failure on one interpreter is a genuine portability finding
# rather than two resolutions that were each free to pick something different.
#
# If a pin genuinely cannot work on one interpreter, add a per-version override
# named constraints-py<minor>.txt (e.g. constraints-py3.11.txt) holding the pins
# that differ; CI prefers that file over this one for that interpreter only.
#
# Captured from a CLEAN virtualenv (`python -m venv`, no site-packages
# inheritance), not from whatever happened to be installed: CPython 3.12.10,
# `pip install -r requirements.txt -r requirements-dev.txt`, then `pip freeze`.
# Verified by running the full suite against these exact pins in that
# environment: 725 checks, exit 0.
#
# Install reproducibly:
#     pip install -r requirements.txt -r requirements-dev.txt -c constraints.txt
#     python run_tests.py
#
# A constraints file only constrains what is actually being installed, so a
# platform-only pin such as pywin32 (captured on Windows) is simply ignored on
# the Linux runners, and CI does not flag it as drift.
#
# CI enforces this file: after installing, it freezes what it actually got and
# requires every installed package to equal its pin here. A package that was
# installed but never pinned fails the job, because an unpinned package means
# this file does not describe the closure and the matrix is not reproducible.
# The freeze is uploaded as the resolved-py<minor> artifact, so a mismatch is a
# diff you can read instead of a mystery.
#
# Regenerate on a machine with that interpreter:
#     python -m venv /tmp/v
#     /tmp/v/bin/pip install -r requirements.txt -r requirements-dev.txt
#     /tmp/v/bin/pip freeze | sort
#
